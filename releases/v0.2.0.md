# v0.2.0

Adds an official command-line entry point. The library (`src/runner.php`), its
API and the SFM execution semantics are unchanged from v0.1.0.

## Command line

`bin/run.php` is part of the Composer distribution. It runs one flow with
`runner::run()`; PHP itself is the executable, with no new dependencies,
binaries, PHAR or CLI framework.

```bash
php vendor/divengine/runner/bin/run.php flows/order.yml --context input.json --root functions --save-context state.json
php vendor/divengine/runner/bin/run.php flows/order.yml --context state.json --save-context state.json
```

- Options: `<flow>` (`.yml`, `.yaml` or `.php`), `--context <file>` (JSON
  object), `--root <dir>` (sets `_root_folder`), `--save-context <file>`,
  `--json`, `-h`/`--help`. Relative paths are relative to the working directory.
- stdout carries only the result: the final state (`done`, `paused`, `error`)
  or, with `--json`, the resulting context. Diagnostics go to stderr, and so does
  anything the flow prints, PHP warnings included.
- Exit codes: `0` done, `3` paused, `1` error (failing step or setup error such
  as invalid YAML), `2` invocation error. Code `2` covers bad arguments and
  unreadable input, in which case the flow does not run. It also covers a context
  that could not be saved or printed as JSON.
- The project's Composer autoloader is loaded, so flows can use project classes
  without an application bootstrap.
- Optional project shortcut: a `run` file with
  `require __DIR__ . "/vendor/divengine/runner/bin/run.php";` enables
  `php run flows/order.yml`. PHP installs no global `run` command.

## JSON persistence

- Pause and resume work across separate PHP processes, including pauses inside
  nested calls. Steps that already ran are not repeated.
- `--save-context` writes a temporary file in the same folder and renames it, so
  a partial file is never visible; the permissions of a replaced file are kept.
- Before anything is written, the context must contain only values that come
  back unchanged from JSON: `null`, booleans, integers, floats, strings and arrays
  of them, at most 512 levels deep. Objects (closures included) and resources are
  rejected at any depth, and so are recursive arrays. Encoding uses
  `JSON_THROW_ON_ERROR` (`NAN`, `INF`, invalid UTF-8) and
  `JSON_PRESERVE_ZERO_FRACTION` (floats stay floats).
- On any of these failures the command prints the path of the offending value
  on stderr, prints nothing on stdout, exits with `2` and leaves the existing
  saved context untouched.
- Missing or unwritable inputs and save folders are reported before the flow
  runs.

## Limitations

- Flows, activities and conditions are trusted PHP code; the command line is not
  a sandbox, and a context file can set reserved keys such as `_root_folder` and
  `_modules`.
- A flow that calls `exit()` or hits a PHP fatal error ends the process with
  PHP's own status, and nothing is saved.
- An empty JSON object `{}` comes back as an empty array `[]`.
- No scheduler, queue, worker, daemon, job database, stdin context or log
  streaming.

## Quality

- `tests/CliTest.php` installs the package offline with Composer from a
  distribution archive and runs the installed `bin/run.php` in fresh processes.
- The installation smoke test pauses and resumes the example flow through the
  installed command line.
- CI covers PHP 8.1 to 8.5 and PHPStan, which now also analyses `bin/`.
