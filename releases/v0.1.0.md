# v0.1.0

First stable release of Divengine Runner, a lightweight PHP engine for
Sequential Flow Model (SFM) flows. One source file, one class, no runtime
dependencies. Requires PHP 8.1 or newer (tested on 8.1–8.5).

## Features

- Run PHP callable flows (`function (array &$context)`) or PHP files that return one.
- Run YAML flows: `runner::run()` / `runner::runYaml()` compile them on the fly.
- Compile YAML to PHP: `runner::generateFlowCodeFromYaml()` (deterministic output)
  and `runner::flowFromYaml()`.
- Shared mutable context with run metadata (`_runner_state`, `_runner_result`,
  `_runner_error`, `_runner_logs`, timestamps).
- Ordered blocks and steps with `condition`, `context`, `call`, `activity`, `jump`
  and `pause`, in the order of the Python SFM reference runtime.
- `call` returns into the calling step; `jump` transfers control without
  returning and restarts the nearest invocation of its target.
- Pause and resume through the context (`_flow_state`, `_flow_stack`) at any
  call depth, pause requested by activities, `_autoresume`.
- `runner::run()` removes its own helpers before returning, so a context of
  plain data can be stored as JSON and resumed in another process.
- After an error the resume state is cleared and the next run starts at the
  first block.
- Flows used as activities run in their own control scope; a pause inside them
  ends that child invocation early (result `null`) and the parent continues.
- Optional step `module`: module-qualified activities and conditions resolve
  only inside their module folder (`_modules` or `<root>/<module>`), so equal
  names in different modules do not collide.
- Unqualified resolution: PHP files under `_root_folder` /
  `DIV_RUNNER_ROOT_FOLDER`, paths, then callable names (Composer autoload).
- Built-in YAML parser for the flow DSL: block scalars, one-line flow
  collections, comments; verified against the fixture flows of the Python SFM modeler.
- Schema validation of flow, block and step keys and values; invalid targets
  fail at compile time.
- Recursive calls limited by `_max_call_depth` (default 256).
- Logging through `runner::setLogger()` or the `logger` run option.

## Compatibility

See `docs/sfm-compatibility.md`. Known divergences from the Python reference
runtime: call continuations survive a pause, the YAML root key is `blocks`
(mappings only), and module folders are plain folders instead of framework
addons.

## Security

YAML flows are compiled to PHP and run with `eval()`, and functions are loaded
with `require`. Flows are trusted code; Runner is not a sandbox. See
`docs/security.md`.

## Not included yet

Context persistence and storage sanitization, `_progress` reporting, YAML files
as activities, jump-loop limits, modeler/simulator features.
