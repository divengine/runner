# v0.3.0

Adds opt-in **semantic tracing** and **side-effect-free simulation**. Both run
on Runner's own compiler and runtime: the wrappers that already execute
conditions, activities, `call`, `jump` and `pause` record the events, and a
simulation answers every function reference from declared test doubles. The
SFM execution semantics of `runner::run()` are unchanged, and `run()` stays
untraced.

## Tracing

`runner::runTraced(string|callable $flow, array &$context, array $options = []): array`
runs a flow exactly like `run()` and returns a trace document.

- **Protocol** `divengine.runner.trace`, version `1` (`runner::TRACE_PROTOCOL`,
  `runner::TRACE_VERSION`), specified in `docs/tracing-and-simulation.md` and
  `docs/trace.schema.json`.
- **Envelope:** `mode`, `flow`, `fingerprint`, `sources` (each file with its
  SHA-256), `limits`, `budget`, `result`, `simulation`, `truncated`,
  `truncation`, `events` and `meta` (start time, duration, PHP version: the only
  nondeterministic part).
- **26 event types**, each with `seq`, `type`, `flow_depth` and `call_depth`:
  block entries and their reason, started and skipped steps, condition outcomes,
  activity start, end, error and pause with context `changes`, `call` (returns),
  `call.return`, `call.drop` and `jump` (does not return) as separate events,
  `pause` with the exact `_flow_state` / `_flow_stack` checkpoint, nested flow
  scopes, flow logs, doubles, missing functions, budget exhaustion and
  truncation.
- **Tracing observes, it does not change.** The context ends exactly as after
  `run()`, with the same keys in the same order. Trace state is never stored in
  the context, so nothing reaches a saved checkpoint. A `run()` call made by an
  activity is a separate, untraced invocation.
- **Setup errors** (unreadable or invalid flow) are recorded in the context and
  in `result.setup_error` instead of being thrown, so a trace is always
  returned. Invalid trace options throw `InvalidArgumentException` before
  anything runs.

### Values, secrets and size

- **JSON-safe values:** closures, objects, resources, `NAN`/`INF` and invalid
  UTF-8 become `{"$type": ...}` markers.
- **Caps** (option `trace`): `max_events` 10000, `max_bytes` 4 MiB (minimum
  8192), `max_string` 1024, `max_items` 100, `max_depth` 8, `max_nodes` 2000,
  plus `capture_values`, `redact_keys`, `redact_defaults` and `exclude_keys`.
  Keys past `max_nodes` and keys longer than `max_string` are counted, not
  copied.
- **Strict size bound.** The kept events, one compact JSON line each, never
  exceed `max_bytes`. Ordinary events use at most three quarters of it; the
  forced events `budget.exhausted`, `run.end` and `trace.truncated` (once each)
  use the rest and are compacted until they fit, so `run.end` is always
  present. Fields cut this way become `{"$type": "truncated", "reason":
  "max_bytes"}`. `truncation` reports `dropped_events` and `compacted_events`.
  Caps only truncate the trace; they never stop or change the run.
- **Redaction by key**, at any depth, for keys that look secret (`password`,
  `token`, `api_key`, `authorization`, `cookie`, `card_number`, …) plus
  `redact_keys`.
- **Messages are left out by default.** Error and log messages are free text,
  so the trace replaces them with `{"$type": "redacted"}` unless
  `capture_messages` is true. The logger, `_runner_logs`, `_runner_error`,
  `_runner_result` and stderr still receive full messages.

## Simulation

`runner::simulate(string $yamlPath, array &$context, array $doubles, array $options = []): array`
runs a YAML flow through the same runtime with test doubles and returns its
trace.

- **No function is loaded or called.** Every condition and activity reference
  resolves to a declared double; no function file is required and no callable
  name is resolved. A reference without a double emits `function.missing` and
  ends the run in `error`; it never falls back to real code. PHP flows are
  refused before anything runs.
- **Doubles:** `{"returns": value}`, `{"throws": "message"}`, `{"pause": true}`
  (activities only), each optionally with a `context` merge;
  `{"sequence": [...]}` for one outcome per call; `{"flow": "child.yml"}` for a
  nested YAML flow simulated with the same doubles. Keys are `module:name` or
  plain names, after `function_map`.
- **Pause and resume** follow Runner's own `_flow_state` / `_flow_stack`
  behavior. `double_calls` carries sequence positions to the next segment, and
  `fingerprint` refuses to resume when the flow, the doubles, a nested flow or
  the `function_map` changed.
- **Execution budgets:** `steps` 10000, `transfers` (calls and jumps) 10000 and
  `seconds` 10 (wall clock) per invocation, plus a `cancel` callable checked at
  every step and transfer. Exhaustion records `budget.exhausted` and ends the
  run in `error` with the usual reset of the resume state.
- Options: `budget`, `cancel`, `double_calls`, `fingerprint`, `trace`,
  `function_map`, `logger`, `shared_context`. Invalid doubles or options throw
  `InvalidArgumentException` before anything runs.

## Command line

New options of `bin/run.php`; existing options, stdout and exit codes are
unchanged.

| Option | Effect |
|---|---|
| `--trace <file>` | Also write the trace as JSON (atomic replace). |
| `--trace-messages` | With `--trace`: keep error and log messages in the trace. |
| `--simulate <file>` | Simulate a YAML flow with the doubles of a JSON file `{"doubles", "budget", "trace", "description"}`. Refuses `--save-context`, `--root` and PHP flows. |
| `--session <file>` | Simulation state across processes (`divengine.runner.simulation-session` v1), resumed when the file exists. A file that is not a session, such as a normal-run checkpoint, is refused and left untouched. |

```bash
php vendor/divengine/runner/bin/run.php flows/invoice.yml --simulate doubles.json \
    --context context.json --session session.json --trace trace-1.json   # paused, exit 3
php vendor/divengine/runner/bin/run.php flows/invoice.yml --simulate doubles.json \
    --session session.json --trace trace-2.json                          # done, exit 0
```

Exit `1` also covers an unmocked function, a double that throws and an
exhausted budget. Exit `2` also covers an invalid doubles, budget or session
file, a changed source, and a trace or session file that could not be written.
`--trace` and `--session` must differ from every input file and from each
other.

## Compatibility

- **No breaking API change.** `run()`, its options and its behavior are
  unchanged; the additions are `runTraced()`, `simulate()`, the two constants
  and the CLI options above.
- **Generated flow code** now passes the step id to `checkPause`
  (`$checkPause(N, $context, 'step')`). The new parameter is optional: PHP flows
  generated by earlier versions keep working; in their traces, step start and
  skip events carry `step: null`.
- **Protocol stability.** Within version `1`, fields, event types and enum
  values may be added; consumers must ignore unknown ones. Removing or renaming
  them, or changing their meaning, bumps the version. A session resumes only
  with an unchanged fingerprint, so a later Runner may refuse an older session.
- No new dependencies. `composer.json` and the GPL-3.0-or-later license are
  unchanged. `docs/` and `examples/` are not part of the Composer distribution.

## Limitations

- **Normal execution has no execution budget yet.** `run()`, `runTraced()` and
  `bin/run.php` without `--simulate` have no step, transfer or time limit; an
  endless `jump` loop runs until stopped. Budgets apply to simulations only.
  Budgets for normal runs are tracked in #31. Recursion depth stays limited by
  `_max_call_depth` in every run.
- **Simulation scope:** YAML flows only, nested flows only as YAML doubles;
  doubles are data, not PHP callables; a condition double cannot pause.
- **Not a sandbox:** simulation guarantees only that the flow's functions are
  not loaded or called. The flow and nested flows are compiled and run in the
  same PHP process, without OS isolation; flows and doubles files are trusted
  inputs.
- **Budget timing:** wall-clock time is checked at every step and transfer; CPU
  time is not measured.
- **Diff granularity:** context changes compare top-level business keys (keys
  not starting with `_`).
- **Redaction** is by key name; values under other keys are kept (within the
  caps). Context and session files hold `_runner_error` and `_runner_result`
  with full messages, as saved contexts always did.
- An empty JSON object `{}` appears as `[]`.

## Quality

- `tests/TraceTest.php`: golden traces (ordinary run, skipped condition, context
  diff, call and return, jump, failure, pause and resume, budget exhaustion);
  traced and untraced runs give identical contexts; simulations load no
  function file; message redaction; `function_map` fingerprints; size stress
  tests across a matrix of caps and payloads.
- `tests/CliTest.php` runs the new options and the `examples/simulation`
  segments against the Composer-installed package in fresh processes.
- The installation smoke test also traces the example flow and simulates it
  across two processes through the installed command line.
- CI covers PHP 8.1 to 8.5 and PHPStan.
